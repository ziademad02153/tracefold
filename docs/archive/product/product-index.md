# Tracefold product requirements

> Historical record. For authoritative documentation use [the documentation index](../../README.md). Commands and conclusions below reflect the recorded stage; use the current development guide for execution.

Tracefold is an early AI-assisted testing platform. Python is the first validated provider, not the core platform identity. Current deployment is a single-user local pilot.

The current product/navigation source of truth is [PRODUCT_BLUEPRINT.md](product-blueprint.md). The implemented repository workflow and acceptance evidence are in [M4.md](../validation/m4.md): connect repository, prepare environment, run existing tests, generate additional tests, review/approve, execute, save evidence and replay the same suite after a repair.

[REPOSITORY_TESTING_ROADMAP.md](../roadmap/repository-testing.md) defines M1–M4 and the pending company-project gate. [ARCHITECTURE_REVIEW_M4.md](../architecture/m4-review.md) records current core/provider boundaries and open findings. [LANGUAGE_EXPANSION_ROADMAP.md](../roadmap/language-expansion.md) is future direction, not delivered language support.

SPRINT1.md, SPRINT2.md and SPRINT3.md retain the historical function/file implementation and validation records. Their narrower scopes are compatibility tools, not a description of the full current repository workflow. Company readiness and shared daily deployment remain separate acceptance gates.
